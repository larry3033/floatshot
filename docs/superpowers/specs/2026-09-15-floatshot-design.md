# FloatShot 设计文档

**日期**：2026-09-15
**状态**：待实施
**目标目录**：`openprogress/floatshot/`

---

## 1. 目标

一个 Windows 桌面截图贴图工具：按全局热键框选屏幕区域后，截图以置顶悬浮窗的形式留在桌面上，可自由拖动、缩放、关闭。

### 非目标（明确不做）

- 图片编辑、标注、马赛克
- 多图管理、历史记录、图库
- 滚轮缩放、贴边吸附、双击复制（用户明确选择首版不做）
- 跨平台（本设计深度依赖 Win32 API，仅 Windows）

---

## 2. 已验证的关键决策

以下决策均有实测数据支撑，非推断。

### 2.1 禁用 Qt 高 DPI 缩放，改用系统 DPI 手动补偿

**问题**：Qt 6 默认开启高 DPI 缩放。在 125% 缩放下，逻辑坐标 1536 对应物理像素 1920，鼠标选区的逻辑坐标直接喂给抓屏函数会截错区域。

**方案**：进程启动时禁用 Qt 缩放，使**逻辑坐标恒等于物理像素**，抓屏与鼠标坐标天然 1:1，零换算代码。

**实测数据**（本机 1920×1080）：

| 指标 | 100% 缩放 | 125% 缩放 |
|---|---|---|
| `GetDpiForSystem()` | 96 | 120 |
| `QScreen.geometry()` | 1920×1080 | 1920×1080 |
| `devicePixelRatio` | 1.0 | 1.0 |
| `grabWindow()` 结果 | 1920×1080 | 1920×1080 |

125% 下 geometry 仍为 1920×1080（而非 1536×864），证明确实工作在物理像素坐标系。

**代价**：UI 控件不再自动放大。悬浮窗本身不受影响（本就该按图片物理像素显示）；未来的设置界面在高分屏上偏小，需用下方 §2.2 的缩放因子手动补偿。

### 2.2 UI 尺寸 = 固定基准像素 × DPI 缩放因子 + 百分比兜底

**为什么不用纯百分比**：判定区宽度应匹配鼠标精度，而人手能精确控制的像素范围大致固定（约 5–8px），与窗口尺寸无关。纯百分比在两端都会翻车：

| 窗口尺寸 | 固定 6px 判定 | 百分比 2% 判定 |
|---|---|---|
| 100×80 | 6px，抓得住 | 2px，**点不中** |
| 600×400 | 6px，正常 | 12px，略宽 |
| 1920×1080 | 6px，正常 | 38px，**误触缩放** |

小窗口恰恰最需要精确操作，纯百分比在那里判定最窄，方向正好相反。

**三层策略**：

```python
scale = GetDpiForSystem() / 96.0          # 100%→1.0, 125%→1.25, 150%→1.5

# 层 1：主规则 —— 固定基准 × DPI，保证跨屏手感一致
grip = ceil(config.grip_px * scale)
d    = ceil(config.close_diameter_px * scale)

# 层 2：兜底 —— 百分比 clamp，防极端窗口下的退化
grip = min(grip, min(w, h) / 3)           # 防四角判定区互相重叠
d    = min(d, min(w, h) * 0.3)            # 防小窗口时按钮占满画面

# 层 3：判定区大于视觉尺寸（可用性常识）
hit_radius = d * 0.75
```

**取整策略定为 `ceil`**：125% 下 `6 × 1.25 = 7.5`，`ceil` 取 8。判定区宁大勿小，且层 2 的 clamp 已防止过大。

### 2.3 DPI 感知声明

`SetProcessDpiAwarenessContext(-4)`（PER_MONITOR_AWARE_V2）在 Qt import 之前调用。

**实测发现**：本机源码运行方式下，该调用返回 False（已被占用），且 `--no-aware` 对照模式输出与正常模式**完全一致**——说明 python.exe 自带 manifest 已声明 DPI 感知，运行时调用在开发阶段是冗余的。

**仍然保留的理由**：PyInstaller 打包后的 exe 使用 bootloader 自有 manifest，不保证声明 DPI 感知。缺少声明时 Windows 会对整个程序做位图拉伸，`GetDpiForSystem()` 恒返回 96，界面模糊。

**为什么声明 PER_MONITOR_AWARE_V2 而非 System DPI Aware**：即使首版只用系统 DPI（见下文限制），也必须是 per-monitor 级别。若声明为 System DPI Aware，当窗口被拖到 DPI 不同的显示器上时，Windows 仍会对进程做位图拉伸，导致模糊且坐标失真。声明 v2 保证 Windows 完全不干预我们的坐标系，换算全由自己控制——首版虽只用系统 DPI，但为将来支持 per-monitor 留了余地。

**⚠ 未验证项**：打包后 exe 的 DPI 行为无法在本机验证，列为打包验收必测项（§7.3）。

## 3. 模块结构

```
openprogress/floatshot/
├── main.py                  # 入口，仅数行
├── config.json              # 首次运行自动生成
├── requirements.txt         # 仅 PySide6
├── docs/superpowers/specs/  # 本文档
└── floatshot/
    ├── __init__.py          # DPI 环境变量在此，必须在 Qt import 之前
    ├── dpi.py               # DPI 探测与 UI 缩放因子
    ├── metrics.py           # 元素尺寸与判定区计算        ← 纯函数
    ├── geometry.py          # 边缘命中、等比缩放、坐标换算  ← 纯函数
    ├── config.py            # 默认值 + 加载/保存/深合并     ← 纯逻辑
    ├── hotkey_spec.py       # "Ctrl+Alt+Q" ↔ Win32 键码    ← 纯函数
    ├── hotkey.py            # RegisterHotKey + nativeEventFilter
    ├── capture.py           # QScreen.grabWindow 抓屏
    ├── overlay.py           # 全屏选区遮罩
    ├── float_window.py      # 悬浮窗本体
    ├── tray.py              # 托盘图标、菜单、诊断信息
    └── app.py               # 组装、生命周期、信号连线
```

### 依赖约束

**运行依赖只有 PySide6 一个。** 抓屏用 `QScreen.grabWindow` 而非 `mss`，图像处理用 Qt 而非 Pillow。理由：项目要打包 exe 分发，单依赖意味着 PyInstaller 打包体积与失败率都显著更低，出问题时也便于远程排查。

### 为什么把纯函数独立成模块

`metrics.py`、`geometry.py`、`hotkey_spec.py`、`config.py` 均为**无 Qt 依赖的纯函数模块**，是 TDD 的落点。拖拽缩放判定是这类程序最容易出 bug 处，抽为纯函数后可靠断言覆盖极端情况，无需在屏幕上用鼠标试。

## 4. 配置层

### 4.1 位置

程序目录旁的 `config.json`。选择理由：需打包分发，便携式配置让用户拷贝目录时配置跟随；调试时可直接编辑。

### 4.2 结构

```json
{
  "hotkey": "Ctrl+Alt+Q",
  "shadow": { "padding": 18, "layers": 12, "max_alpha": 26, "offset_y": 3 },
  "close_button": { "diameter_px": 16, "fade_ms": 120, "hover_opacity": 0.85 },
  "resize": { "grip_px": 6, "min_width": 80, "min_height": 60 },
  "scale_mode": "free",
  "overlay": { "dim_alpha": 110, "border_color": "#4A9EFF", "show_size_hint": true }
}
```

**所有可调项进配置，代码中只留 `DEFAULTS` 兜底，不存在硬编码常量。** 首版虽无设置界面，改配置亦无需碰代码。后续设置界面直接读写此文件。

### 4.3 深合并策略

用户配置与 `DEFAULTS` 递归合并，用户配置缺失的键自动补齐。

**关键理由**：后续版本新增配置项时，老用户的 `config.json` 不会因缺键崩溃。这对分发场景尤其重要——无法手动修别人的配置文件。

**损坏恢复**：JSON 解析失败时备份原文件为 `config.json.bak`，用默认值重建，不阻断启动。

### 4.4 热键格式

字符串形式 `"Ctrl+Alt+Q"`，由 `hotkey_spec.py` 解析为 `(modifiers, vk)`。支持 `Ctrl`/`Alt`/`Shift`/`Win` 与 `A-Z`、`0-9`、`F1-F12`。改热键只需改配置字符串。

**默认值 `Ctrl+Alt+Q`**：避开 QQ 截图默认键 `Ctrl+Alt+A`。

## 5. 核心流程

### 5.1 抓屏时机 —— 先抓后框

朴素流程「显示遮罩 → 拖框 → 截屏」会把遮罩的暗化层和选区蓝框一起截进图片。用 `hide()` + `processEvents()` 规避则引入闪烁与时序竞态。

**正确流程**：

```
按下热键
  ↓
① 立即抓取整个虚拟桌面到内存（此刻遮罩尚未显示，画面干净）
  ↓
② 显示全屏遮罩，用户拖框选区
  ↓
③ 从内存缓存按选区裁剪 —— 不再触碰屏幕
  ↓
④ 弹出悬浮窗，缓存释放
```

截图不可能截到自身，且无闪烁。选区坐标即缓存内的像素偏移，无需换算。

**多屏**：用虚拟桌面矩形覆盖所有显示器，该矩形可能含负坐标（副屏位于主屏左侧时）。

### 5.2 悬浮窗标志

```
Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint | Qt.Tool
+ Qt.WA_TranslucentBackground
```

用 `Tool` 而非 `Window`：托盘常驻程序不应在任务栏堆积缩略图。

### 5.3 阴影实现

在 `paintEvent` 手绘多层递减 alpha 的圆角矩形（层数与 alpha 走配置）。

**不用 `QGraphicsDropShadowEffect`**，两个理由：
1. Qt 的 `QGraphicsEffect` 在 `WA_TranslucentBackground` 顶层窗口上，Windows 平台存在阴影被裁切/渲染异常的历史问题。
2. `QGraphicsEffect` 作用于整棵 widget 树，关闭按钮也会被投上阴影。

自绘方案完全可控、零依赖、无缓存失效问题。对「弱阴影」量级，约 20 行代码足够。

### 5.4 窗口几何

窗口比图片四周各大 `shadow.padding` 像素，多出区域用于绘制阴影和容纳关闭按钮：

```
┌──────────────────────────────┐  ← 窗口边界（全透明）
│            ╭───╮             │
│        ┌───┤ × ├───┐         │  × 圆心在图片右上角顶点
│        │   ╰───╯   │         │    默认 opacity 0，悬停淡入
│        │           │         │
│        │  图片内容  │         │  ← 拖动 / 八方向边缘缩放
│        └───────────┘         │
│         ↑ 阴影向外渐隐         │
└──────────────────────────────┘
```

新窗初始位置：图片左上角对齐原选区左上角，视觉上截图"原地变成"悬浮窗。

### 5.5 两种缩放模式

| 操作 | 行为 | 绘制方式 |
|---|---|---|
| 拖边框 | 自由拉伸，窗口比例随鼠标 | `drawPixmap` 铺满客户区，**图片变形** |
| `Shift` + 拖边框 | 等比缩放 | **窗口尺寸被约束为原图宽高比**，图片填满窗口且**不变形** |

Shift 模式采用「约束窗口比例」而非「窗口自由变+图片居中留白」：后者在拖动时窗口边框跟着鼠标跑、图片却缩在中间，视觉上松散且与「等比缩放」的直觉不符；前者整个窗口随比例联动，无留白，是截图贴图类工具的通行做法。

比例约束算法：由鼠标位置算出目标宽度（或高度），另一维按 `原图高/原图宽` 推导，取两维中变化量较大的一侧为准，避免拖角时抖动。

命中检测按八方向（四边 + 四角）返回对应光标形状，计算全部在 `geometry.py`。

## 6. 托盘

- 图标常驻
- 菜单：截屏 / 诊断信息 / 退出
- 关闭悬浮窗不退出程序（常驻后台）

**诊断信息**：显示当前探测到的系统 DPI、缩放因子、由 `metrics.py` 算出的 grip 与按钮尺寸。用途是替代本机无法完成的跨 DPI 验证——分发给他人前让其点开一眼即可确认 DPI 探测是否正确。

## 7. 测试策略

### 7.1 单元测试（可断言）

| 模块 | 覆盖点 |
|---|---|
| `hotkey_spec.py` | 键名解析、大小写、非法输入、未知键名、空串、修饰键顺序无关 |
| `geometry.py` | 八方向命中边界、窗口小于 2×grip 时的退化、等比缩放矩形、负坐标 |
| `metrics.py` | 极端窗口尺寸下判定区不重叠、`ceil` 取整、clamp 触发条件 |
| `config.py` | 深合并、缺键兜底、损坏 JSON 恢复、未知键保留 |

### 7.2 手动验收

阴影观感、关闭按钮淡入动画、置顶效果、多屏负坐标行为、缩放拖动手感。

### 7.3 打包验收（必测）

PyInstaller `--onefile --noconsole` 产出后，**必须在未安装 Python 的环境或全新 Windows 用户账号下运行**，重点验证：

1. **DPI 感知是否生效** —— 在 125%/150% 缩放环境下，托盘「诊断信息」应显示正确的 DPI 值而非恒定 96。若显示 96，说明 exe 的 manifest 未声明 DPI 感知（§2.3），需补 manifest 或调整 `dpi.py` 的声明时机。
2. 全局热键能否注册成功
3. 抓屏是否正常（无黑屏、无错位）

此项在开发机上无法验证，是分发给他人前的强制关卡。

## 8. 已知风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 打包后 DPI 感知失效 | 高分屏上界面模糊、`GetDpiForSystem()` 失真 | §7.3 强制验收；`dpi.py` 保留运行时声明 + 回退链 |
| 热键被其他程序占用 | 按下无反应 | `RegisterHotKey` 失败时托盘气泡提示，并提示改配置 |
| 多显示器 DPI 不一致 | 跨屏拖动时元素尺寸不更新 | 首版接受，用系统 DPI 而非 per-monitor；记录为已知限制 |
| 极简窗口下的判定区退化 | 窗口过小无法操作 | 由 `resize.min_width/min_height` 限制最小尺寸 |
